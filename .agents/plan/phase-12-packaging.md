# Phase 12 — Deployment Packaging (Compose First, Kustomize Second)

**Goal:** a household running OpenCloud the way OpenCloud tells it to — with
`opencloud-compose` — adds backups by adding one overlay, not by translating
Kubernetes manifests. And CI tests exactly that overlay against every
OpenCloud version in the window.

**Depends on:** Phase 9 (matrix), Phase 11 (released, versioned images to
reference). **Findings:** review-2026-10.md O8, P1–P4. **Decision:** #27.

## Background: how OpenCloud is deployed

`opencloud-eu/opencloud-compose` is a base `docker-compose.yml` plus optional
overlays selected with `COMPOSE_FILE` (e.g.
`docker-compose.yml:weboffice/collabora.yml:traefik/opencloud.yml:traefik/collabora.yml`).
Relevant to us (measured 2026-10-06 on its `main`):

- OpenCloud image `opencloudeu/opencloud-rolling:${OC_DOCKER_TAG:-8.0.1}`.
- CSP from `./config/opencloud/csp.yaml` via `PROXY_CSP_CONFIG_FILE_LOCATION`;
  `script-src` is `'self' 'unsafe-inline'` + the IdP — **no
  `'wasm-unsafe-eval'`**.
- Web apps from `${OC_APPS_DIR:-./config/opencloud/apps}` bind-mounted to
  `/var/lib/opencloud/web/assets/apps`.
- Traefik terminates TLS and routes by host; each add-on brings
  `traefik/<addon>.yml`.
- Ships its own `renovate.json`.

## 12.1 The compose add-on (primary artifact)

Lives in this repo under `deploy/compose/`, mirroring opencloud-compose's
layout so it can be copied into a checkout of it (and released as an archive,
Phase 11):

```
deploy/compose/
  backup/backup.yml          # backupd + one-shot web-bundle installer
  traefik/backup.yml         # /backup/api route on OpenCloud's host
  config/backup/csp.yaml     # OR documented one-line patch — see 12.2
  backup/.env.example        # variables this add-on reads
  backup/setup.sh            # optional helper, see 12.3
```

Used as:
`COMPOSE_FILE=docker-compose.yml:backup/backup.yml:traefik/opencloud.yml:traefik/backup.yml`.

`backup/backup.yml` contents (behaviour, not final YAML):

- **`backup-vault-web`** (one-shot): the web image copies the bundle into the
  apps directory (`OC_APPS_DIR` bind). `opencloud` gains
  `depends_on: {backup-vault-web: {condition: service_completed_successfully}}`
  so the apps directory is populated before OpenCloud's start-time scan.
- **`opencloud`** (extended, compose merge): `OC_GATEWAY_GRPC_ADDR=0.0.0.0:9142`,
  `STORAGE_USERS_HTTP_ADDR=0.0.0.0:9158` (7.5+; harmless on 7.2? — Phase 9
  measures). **No `ports:`** — reachable on the compose network only.
- **`backupd`**: image by version (and digest in the release archive),
  `read_only: true`, `user: 65532`, `cap_drop: [ALL]`,
  `security_opt: [no-new-privileges:true]`, `tmpfs` for `/work`
  (memory-backed, size-limited) and `/tmp`, `mem_limit` + `GOMEMLIMIT`,
  healthcheck on `/readyz` via the binary itself (distroless has no shell:
  needs a `backupd healthcheck` subcommand — add in this phase),
  `restart: unless-stopped`, **one replica** (compose's default; the
  instance guard still applies).
- `CS3_GATEWAY_ADDR=opencloud:9142`, `CS3_DATA_SERVER_URL=http://opencloud:9158`,
  `OIDC_ISSUER`/`OC_BASE_URL` = `https://${OC_DOMAIN}`, `OIDC_AUDIENCE=web`
  (built-in IdP; the Keycloak overlay differs — documented).

`traefik/backup.yml`: router `Host(${OC_DOMAIN}) && PathPrefix(/backup/api)`
with a priority above OpenCloud's catch-all router, prefix **not** stripped,
same TLS resolver as `traefik/opencloud.yml`. Not `/backup` (would capture
`/backup-vault/…`, deployment-readiness "Known risks").

**Spikes before writing it** (record in `phase-0-findings.md`):

1. **Issuer reachability from inside the compose network.** Tokens carry
   `iss: https://${OC_DOMAIN}`; `backupd` must resolve that name to Traefik
   and trust its certificate (Let's Encrypt in production — fine; the
   self-signed dev certs — not). How do opencloud-compose's other add-ons
   (Collabora, Euro-Office) solve it? Reuse that, do not invent.
2. **Service account in compose.** Where opencloud-compose's OpenCloud gets
   `service_account_id/secret` (generated by `opencloud init` into the config
   volume?) and how `backupd` can be given the same values without the
   operator reading `opencloud.yaml` by hand.
3. Whether compose's `depends_on` on an extended `opencloud` service behaves
   with every overlay combination opencloud-compose documents.

## 12.2 The CSP line

The add-on cannot patch one line inside opencloud-compose's `csp.yaml`.
**DECISION NEEDED**, options:

- **A. Documented one-line edit** of the operator's existing
  `config/opencloud/csp.yaml`. Honest, no drift, one manual step that
  fails late (review W3) unless Phase 14's diagnosis lands.
- **B. Ship a full replacement CSP** the overlay mounts over theirs.
  Zero manual steps, but it silently drops whatever the operator or a newer
  opencloud-compose added (Collabora, Keycloak domains).
- **C. Upstream:** propose `'wasm-unsafe-eval'` in opencloud-compose's
  default CSP (it allows WebAssembly compilation only, not `eval`). Fixes it
  for every extension that uses WASM. Combine with A until merged.

Recommendation: **A + C**, plus a check in `setup.sh` and in the admin view
(Phase 14 W3) that tells the operator precisely which line is missing.

## 12.3 First-run helper (optional, owner to decide)

`backup/setup.sh`, run once from the opencloud-compose directory:

1. generates `SRW_KEY` and `TW_KEY` (32 random bytes, base64) into `.env`
   if absent — never overwrites an existing value;
2. runs `docker compose run --rm backupd provision-state-space` and writes
   `STATE_SPACE_ID` into `.env` (refuses if already set — decision #16's
   orphaning rule);
3. checks the CSP line and the `COMPOSE_FILE` entries;
4. prints what is left to do (restart OpenCloud, add a destination).

It never prints keys to the terminal. Startup still never provisions
implicitly (8c amendment) — the helper is an explicit operator act.

## 12.4 The Kustomize add-on (secondary)

`deploy/kustomize/base` from the existing manifests, plus what review P2
lists as missing:

- dedicated `ServiceAccount`, `automountServiceAccountToken: false`;
- `NetworkPolicy` for backupd: ingress only from the ingress controller on
  8080 and from the kubelet for probes; egress to OpenCloud (9142, 9158, 443),
  DNS, and the S3 targets (namespace-wide egress on 443/3900, documented as
  the operator's to narrow). The OpenCloud-side policy for 9142/9158 stays
  the owner's decision (7.5.0 amendment);
- `startupProbe`; `GOMEMLIMIT` from the limit (downward API);
- Jobs: `provision-state-space`, `rotate-srw`, `rotate-tw`, `takeout`
  (suspended templates);
- the web-bundle initContainer as a patch example for OpenCloud's own
  Deployment, plus — after a spike — how to do it with OpenCloud's Helm chart
  (`opencloud-eu/helm`), which is what most Kubernetes users of OpenCloud run;
- `app.kubernetes.io/{name,version,part-of,component}` labels; images by
  digest in the released archive;
- `overlays/example` with every `REPLACE_ME`.

`kubeconform` validates the rendered output against the oldest and newest
Kubernetes versions the docs claim.

## 12.5 The fixture becomes what ships

Replace the bespoke `test/fixtures/opencloud/docker-compose.yml` + Caddy
proxy with: **opencloud-compose at a pinned commit** + **our compose add-on**
+ a **test-only overlay** (seeded users, test CA, fixed domain). The
OpenCloud tag comes from Phase 9's `versions.yaml`, so every matrix leg runs
the shipped add-on.

- The development loop (`backupd` on the host, `go run`) needs a dev overlay
  that routes `/backup/api` to the host instead of the container; keep it,
  it is what makes iterating fast.
- `seed.sh`, `install-webapp.sh` and the E2E `global-setup` move onto the new
  stack; `make dev-up` keeps its name.
- Renovate bumps the opencloud-compose commit; a bump runs the whole matrix.

Risk: opencloud-compose changes shape (it is under active development —
the WOPI service was folded into OpenCloud recently). Pinning by commit
contains it; the canary (Phase 9) runs against its `main` as well.

## Exit criteria

- [ ] A fresh opencloud-compose checkout + the add-on + `setup.sh` gives a
      working Backup Vault (setup, backup, restore) — walked once by hand on
      a clean machine and automated in CI on every matrix leg.
- [ ] The CSP decision taken; if C, the upstream PR is open.
- [ ] Kustomize base + example overlay render and validate; NetworkPolicy
      tested on a kind cluster with a CNI that enforces it (or recorded as
      untested — not claimed).
- [ ] The bespoke fixture is gone; integration and E2E run on
      opencloud-compose + add-on.
- [ ] Release archives for both add-ons attached by the release workflow.
