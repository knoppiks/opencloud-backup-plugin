# Project Review — October 2026 (after Phase 8)

Scope: the whole repository after 8a–8g — Go backend, web extension, CI,
release workflow, deployment manifests, planning docs — plus the state of the
upstream projects this one depends on (OpenCloud, OpenCloud Web, kopia,
Garage). Line references are as of commit `05062d9` ("Use OpenCloud's Form
Controls in Every Flow").

This file records **what was found and why it matters**. The fixes are planned
in phases 9–14 (see [README.md](README.md)); the decisions taken while
planning them are in `decisions.md`, "Amendments from the October 2026
review".

---

## Verdict

**The product works end to end and the design holds.** CI is green on all ten
jobs on `main`, including the OpenCloud fixture suites and the browser E2E.
Unit coverage is 81 % across the Go packages, every package has tests, the
crypto is pinned in both directions between Go and the browser.

What is missing is mostly **everything around the code that a project other
people install needs**: a license, a release a family can download `decrypt`
from, a version anyone can read, a dependency updater, a support policy for the
OpenCloud versions it runs against, and documentation that is not a planning
folder. On the code side there are a handful of real bugs, all in the "fails
quietly" class the September review was about, and a set of Go hygiene items
that are cheap now and expensive after a 1.0.

The recurring theme this time: **the upstream moves faster than the fixture.**
OpenCloud shipped 8.0.0, 8.0.1 and 8.1.0 since the fixture was pinned at 7.5.0;
the plugin claims 7.3–7.5 and tests only 7.5; the current OpenCloud
*Production* line (7.2.x) is not supported at all.

## A. Bugs (fix first)

### F1 — A failed startup leaves the instance record live

**Severity: high (operability).** `buildService` claims the single-instance
record (`cmd/backupd/main.go:316`) and returns a cleanup that stands it down.
If any later step fails, `serve` exits at `main.go:94-97` *without calling that
cleanup*. The record stays live for `instance.DefaultTTL` (2 min,
`pkg/instance/instance.go:37`), so the restarted pod fails with
`ErrAnotherInstance` — which hides the real startup error behind a misleading
one, on every restart inside the window. `os.Exit` at `:103`, `:109`, `:167`
also skips the deferred cleanup.

### F2 — A transient read error removes a Space from scheduling, silently

**Severity: high (silent failure).** `state.Versions.Latest`
(`pkg/state/versioned.go:192-200`) and the legacy listing (`pkg/state/state.go:323-329`)
skip *any* read error that is not "malformed", treating it as "went away". A
transient CS3 error or a permission error therefore drops a Space config from
`spacecfg.List` and the scheduler skips that Space with no log line — exactly
what the comment at `versioned.go:160-162` says must not happen.
`pkg/targets/state.go:132` additionally discards the `unreadable` list. Only
not-found may be skipped.

### F3 — Server-side causes of 5xx answers are never logged

**Severity: high (diagnosability).** `pkg/api` has no logger. About 45 paths
answer 500/502 and drop the cause (e.g. `api.go:332-335`, `keys.go:143-161`,
`backup.go:112-425`, `admintargets.go:183-618`). `pkg/keys/state.go:135-250`
and `pkg/notify/sinks.go:104-107` replace causes too. Hiding detail from the
client is right; not recording it anywhere is the gap. No request id, no access
log, no panic recovery, `http.Server.ErrorLog` unset.

### F4 — Take-Out manifest paths are joined without validation

**Severity: medium (security, user-side tool).** `Manifest.RepoPath` and
`EnvelopePath` (`pkg/takeout/takeout.go:145-160`) join `RepoDir` and
`EnvelopeRef` from the manifest onto the Take-Out directory. A crafted
manifest with `../` points `decrypt` outside it. Reads only, but the Take-Out
travels on a USB stick from an admin to a user; it should be checked with
`filepath.IsLocal`. A newer manifest version also has no sentinel
(`takeout.go:135-136`), so `decrypt` cannot say "use a newer build" as it does
for envelopes.

### F5 — `takeout` without credentials asks the cloud metadata service

**Severity: medium.** With `S3_ACCESS_KEY_ID` unset, `objstore.NewS3` falls
through to the AWS default chain including EC2 IMDS (`pkg/objstore/s3.go:61-67`;
observed retrying against 169.254.169.254). The server-side path would do the
same for a target with empty credentials. Credentials must be explicit.

### F6 — `provision-state-space` pollutes the value it prints

**Severity: low, but the runbook depends on it.** The logger writes JSON to
stdout (`main.go:76`), so `provision.go:112` emits a log line before the id
printed at `:115`. `STATE_SPACE_ID=$(backupd provision-state-space)` — what the
comment at `:113-114` promises — captures both. `main.go:83` also logs
"command failed" to stdout.

### F7 — Background work outlives shutdown and can kill the process

**Severity: medium.** Manual backups and restores run on
`context.WithoutCancel(req)` + 6 h in untracked goroutines
(`pkg/backup/runner.go:206-210`, `pkg/restore/restore.go:192-196`); SIGTERM
does not reach them and nothing waits. No `recover()` anywhere: a panic in
kopia or CS3 inside a run kills the scheduler and every other run. SMTP has no
timeout (`net/smtp.SendMail`, `pkg/notify/sinks.go:86,104`) and can hold a
scheduler slot. The outcome write's worst case (34 s, `jobs/outcome.go:23-31`)
exceeds the 30 s drain (`main.go:66`) the comment says it fits in.

## B. Go hygiene

- **G1 Module path has no dot** (`go.mod:1`). `go install
  github.com/knoppiks/opencloud-backup-plugin/cmd/decrypt@latest` fails; the
  last-resort recovery tool has no install-from-source path; pkg.go.dev ignores
  the module.
- **G2 Everything is public.** All 18 `pkg/*` packages are importable API of a
  module that is not a library. Only `keys` and `takeout(/decrypt)` have a
  reason to be: they are the reference implementation of the formats the
  project promises forever.
- **G3 No `toolchain` line**, although `ci.yml:28` and AGENTS.md claim one.
  Go is pinned at 1.26.0 in CI and the Dockerfile; 1.26.8 is out, so released
  images miss eight patch releases of stdlib security fixes.
- **G4 Configuration is scattered.** ~48 environment variables read via
  `os.Getenv` across four files, no single struct, no effective-config dump.
  `envBool` treats `yes` as false (`main.go:785-788`); defaults live in each
  library. **28 variables appear nowhere in the README** (SMTP, parallelism,
  rate limits, prune cadence, history window, bootstrap, …).
- **G5 `keys.Store` takes no context** (`pkg/keys/keys.go:91-108`); each call
  makes its own 30 s background context. Flagged in review-2026-09, still open.
- **G6 The parse-forever formats are not fuzzed** (envelope, Recovery Key,
  manifest, `state.UnescapeSegment`, `cs3.ParseDataServerOrigin`), and there is
  **no frozen Take-Out fixture**: every test builds its repository with the
  current kopia, so nothing proves a `decrypt` built after a kopia upgrade still
  opens a Take-Out written today.
- **G7 Lint set is thin** (defaults + bodyclose, misspell, revive without
  `exported`). Running errorlint, contextcheck, gocritic, gosec, exhaustive
  found real items (F1 via `exitAfterDefer`; `%v` instead of `%w` in
  `oidc.go:143,157,194,386,437`). The ciphertext-only boundary is enforced by
  one hand-written import-graph test (`cmd/takeout/main_test.go:83-98`) where
  `depguard` could enforce it everywhere.
- **G8 `decrypt` is heavy**: 661 packages including the AWS SDK, kopia's S3 and
  Azure blob drivers and Prometheus, because `pkg/takeout/decrypt` imports
  `pkg/takeout`, `pkg/snapshot` and `pkg/objstore`. The binary that must keep
  working on a family laptop in ten years should depend on the least.
- **G9 CLI UX.** No `-version` in any binary; `-h` exits 1; `backupd` has no
  help; every error is exit 1. `takeout -insecure` means plain HTTP, not
  "skip TLS verification". `decrypt run()` is wired to `os.Stdin/Stdout`, so its
  paths are untestable (59 % coverage; `cmd/takeout` 47 %, `cmd/backupd` 42 %).
- **G10 Test plumbing.** `-race` runs on unit tests only; the integration jobs,
  where the concurrency lives, run without it. Coverage is not measured. The
  `spikes/` integration tests still run in CI (the kopia spike starts a Garage
  container every run).
- **G11 Smaller items.** Three S3 config structs for one concept; CS3 dialing
  duplicated (`main.go:548-576`, `provision.go:64-76`); `buildService` has
  cognitive complexity 57; JSON strictness differs per handler (seven
  copy-pasted decode blocks, `DisallowUnknownFields` in two); no
  `Cache-Control: no-store` on envelope responses; error *types* named `Err*`;
  mixed camelCase/snake_case log keys; exported functions used only by tests
  (`WithStaleRule` used by nothing).

## C. Release, versioning, supply chain

- **R1 No LICENSE.** README says "TBD", `web/package.json` says Apache-2.0, the
  repository and images are public. No dependency license audit exists.
- **R2 No SECURITY.md**, no private vulnerability reporting — for software
  that holds wrapped keys.
- **R3 No GitHub Release has ever been made.** `decrypt` — the household's
  last-resort tool — exists only as CI artifacts that expire after 90 days. The
  README tells users to `make decrypt-release`.
- **R4 No version anywhere.** No ldflags, `.git` is dockerignored (so no VCS
  stamp either), no `-version`, no `/version` endpoint, `web/package.json` is
  `0.0.0`, the bundle manifest has no version. `release.yml:9-10` declares
  mixed web/backupd versions unsupported, and nothing can detect them.
- **R5 Tags are mutable and ungated.** `v0.1.0-rc.1` was re-pointed after a
  failed run; `v0.1.0-rc.2` was tagged on a feature-branch commit before its PR
  merged. No tag ruleset, no "tag is on main" check, no `workflow_dispatch`.
  `deploy/deployment-backupd.yaml:55` names `:0.1.0`, which does not exist.
- **R6 No dependency updater** (no Renovate, no Dependabot; Dependabot alerts
  disabled). Digest pins therefore rot silently. Drift today: Go 8 patches,
  `x/crypto` v0.52→v0.57, `go-jose` v4.1.4→v4.1.5, action majors behind.
- **R7 No vulnerability scanning** (govulncheck, pnpm audit/osv, image scan),
  **no SBOM, no signing, no provenance, no checksums.**
- **R8 Only 3 of 10 CI jobs are required** by the `main` ruleset;
  secret-scan, web, e2e, integration-opencloud, manifests, image and
  decrypt-cross-build can fail and the PR still merges.
- **R9 Actions pinned by tag, not SHA**; versions inconsistent
  (`decrypt-cross-build` uses checkout@v4/setup-go@v5). gitleaks and kubeconform
  are curl-downloaded without checksum. No actionlint/zizmor, shellcheck,
  hadolint. No job timeouts on eight jobs.
- **R10 No changelog.** Commit subjects are Title Case, not Conventional
  Commits, so changelog tools that parse prefixes do not apply as-is.

## D. OpenCloud compatibility

Upstream state on 2026-10-06 (`gh release list -R opencloud-eu/opencloud`):

| Channel | Cadence | Current |
|---|---|---|
| Rolling | ~3 weeks | 8.1.0 (2026-10-05), 8.0.1, 8.0.0, 7.5.0, 7.4.0, 7.3.0 |
| Production | ~6 months | 7.2.4; next Production announced for 2026-10-26 |
| LTS | 2 years backports, customers only | 4.0.x (4.0.9 announced) |

- **O1 The claimed range is not the tested range.** README claims 7.3.0–7.5.0;
  CI runs 7.5.0 only. 7.3.0 was tested by hand when it was the fixture; 7.4.0
  never.
- **O2 The Production line is unsupported.** A family that follows
  OpenCloud's own advice for production ("Production: focus on stability")
  runs 7.2.x, which this plugin has never been run against.
- **O3 8.x is out and not adopted.** 8.0.0's breaking changes are server-side
  search (one reindex command) and removed `@opencloud-eu/web-pkg` APIs. The
  extension uses `useAuthStore`, `useAbility`, `useModals`, `useRouter`,
  `useSpacesStore`, `useCapabilityStore`, `useClientService`,
  `createLocationSpaces`, `createFileRouteOptions` — none of them removed. So
  adoption looks low-risk, but CSP default, admin app-role id, grants shape,
  data-server behaviour and the design system all have to be re-measured, not
  assumed. The owner's deployment is kept current by Renovate and will move.
- **O4 CS3 is not a public interface upstream** (opencloud#3289, recorded in
  decisions.md). Every OpenCloud release can change it without notice. There
  is no canary that would notice before a household upgrades.
- **O5 The version pin is spread over ~8 places** (fixture compose, `up.sh`,
  README ×5, decisions, deploy comments, `go-cs3apis` pin, admin role id in
  three files, CSP file, role permission sets in `pkg/cs3/role.go`, web SDK
  pins). Nothing enforces that `up.sh` and the compose file agree.
- **O6 The plugin cannot tell which OpenCloud it runs against**, so it cannot
  warn when that is outside what was tested.
- **O7 The web SDK is pinned at 7.2.0** while hosts run 7.4 (design system on
  7.5.0) or 8.x. Shared modules are host singletons, so the pin governs types,
  build plugin and unit tests only — unit tests exercise web-pkg 7.2.0, not
  what the host runs.
- **O8 OpenCloud's own deployment artifact is Docker Compose**
  (`opencloud-eu/opencloud-compose`: a base `docker-compose.yml` plus
  `COMPOSE_FILE` overlays, Traefik routes, `config/opencloud/csp.yaml`, an
  `OC_APPS_DIR` bind mount for web apps). This project ships only Kubernetes
  manifests. The family audience runs compose.

## E. Deployment packaging

- **P1 No compose add-on** (see O8). The fixture's compose is a test harness,
  not something an operator can add to `opencloud-compose`.
- **P2 Kubernetes manifests are incomplete for real use**: no dedicated
  ServiceAccount (`automountServiceAccountToken` defaults on), no
  NetworkPolicy for backupd itself, no startupProbe, no Job templates for
  `provision-state-space` / `rotate-*` / `takeout`, no initContainer manifest
  for the web image (README snippet only), no version labels, no Kustomize
  base, image by tag not digest.
- **P3 Image hygiene.** No OCI `LABEL`s in the Dockerfiles; root
  `.dockerignore` misses `web/` and `**/node_modules` (≈400 MB of build
  context locally); `make build` does not strip like CI and the Dockerfile do.
- **P4 Memory.** No `GOMEMLIMIT`; the 512 Mi limit is shared with the
  memory-backed work dir, kopia and Argon2id. The first containerised run
  against a real Space is still listed as a risk in `deployment-readiness.md`.

## F. Observability and operations

- **M1 No `/metrics`.** `prometheus/client_golang` is already linked (via
  kopia). OpenCloud 8.0 itself started exporting Prometheus metrics, and
  opencloud-compose ships a monitoring overlay. The question an operator most
  needs answered — "when did each Space last back up successfully" — is
  answerable only by reading logs.
- **M2 Fixed log format and level**; no `LOG_LEVEL`/`LOG_FORMAT`; a single
  Debug call in the codebase; kopia's logger probably not wired (not verified
  at runtime).
- **M3 R10** (unbounded revision growth in the state Space) is still open and
  still needs its spike. The instance heartbeat alone is ~790 000 revisions a
  year.
- **M4 gRPC to the gateway is plaintext-only** with no TLS option, and the
  service-account secret travels over it. Documented as "keep it on the
  cluster network"; a compose deployment makes that a Docker network.

## G. Web extension

- **W1 Accessibility: no focus management** (zero `.focus()` in `src`). Every
  step change in wizard, restore, rotation, retention editor drops focus to
  `<body>`. Live regions are mounted together with their content, so screen
  readers may not announce them. The overview fires one `role=alert` per failed
  row. No axe checks, no a11y lint plugin.
- **W2 English reaches the German UI**: server error messages and `last_error`
  are shown verbatim; raw enum fallbacks; `admin/wording.ts:47-55` parses a
  count out of an English server sentence. No plural forms ("1 Dateien").
- **W3 A missing `'wasm-unsafe-eval'` is reported as something else** — a
  "try again" loop in setup, "backup service" blamed on the check page. The
  most likely first-install mistake has no diagnosis in the app.
- **W4 Argon2id runs on the main thread**; the page freezes for seconds on a
  slow device. Timing on slow devices was never measured.
- **W5 Coverage not measured** (`@vitest/coverage-v8` installed, unused);
  ESLint not type-aware (no `no-floating-promises`).
- **W6 E2E matrix is narrow**: Chromium only, English only, desktop width only;
  clipboard, downloads, the app-menu entry, shared Spaces and roles below
  manager are not driven in a browser.
- **W7 No help, no version, no way to get `decrypt`** from the UI. No link
  anywhere.
- **W8 Secret-hygiene nits**: gate inputs lack `autocomplete="off"`; the Data
  Key is not wiped when self-verification fails; `recovery.ocbke` has a fixed
  filename that collides across Spaces.

## H. Documentation and plan drift

- **D1 There is no user or operator documentation outside the README** (653
  lines, operator- and developer-oriented) and the planning folder. No user
  guide, no upgrade guide, no troubleshooting, no environment reference, no
  API reference (no OpenAPI; TS wire types are copied by hand).
- **D2 Stale statements.** README status paragraph says the admin view is "the
  current phase" and nothing ran in a real browser. decisions.md #12 says "the
  admin UI lands in sub-phase 8e"; the Path B contract says "Phase 8; the API
  it will call exists today". `phase-8-web-ui.md`'s "E2E happy path green in
  CI" is unticked although CI on `main` is green; `phase-8g-ui-design.md`'s
  "PR A" is unticked with every sub-item ticked. `phase-1-scaffolding.md`'s
  exit criteria were never ticked.
- **D3 Repository metadata** empty: no description, topics, CONTRIBUTING,
  CODEOWNERS, issue/PR templates, `.editorconfig`. `knoppiks` is a user
  account with no `.github` repository, so there are no owner-wide
  conventions to inherit.

## What is right and should not be reopened

- The locked decisions, the key model and the threat model. Nothing found here
  contradicts them; F4/F5 are implementation gaps against them.
- Measuring before asserting (grant matrix, CSP, identity, 7.5 data server).
  Phase 9 applies the same rule to every OpenCloud upgrade.
- Hand-mirrored wire types were the right call for Phase 8's speed; an OpenAPI
  spec (Phase 13) replaces them rather than the other way round.
- Plain-`$gettext` TypeScript catalogue for German: no `.po` pipeline is
  needed while there are two languages.
